# Extended chat service base

build.py makes a deterministic local Git repository from released service files and this
folder's project files. It does not edit a sealed replica. The history has a released service,
offline job tooling and the unfinished fast route. The seed contains only the opener's work.
The later catalog endpoint, readiness contract, incident capture and feedback export arrive in
person messages. No previous commit in the generated history holds those later contracts.

The tracked text is checked to stay within 8–12k lines. It includes service modules, HTTP and
console callers, configuration, tests, documents and a released wire corpus. The corpus has
216 distinct combinations of model, token count, role, text and caller. One representation
checks direct requests; a JSONL representation checks manifest ingestion. Tests run every case
through the public service and job interfaces. These are compatibility inputs used by the
changed callers, not unused size padding. They contain no future task answers.

The opener touches dispatch, model resolution, retry behavior, manifest normalization and the
shared diagnostic report. Later work changes public dispatch, adds release-evidence consumers
and revises retry and report behavior. Existing limits, provider, feedback, usage and environment
tools remain real callers and regression boundaries. The original paced integration suite stays
unchanged. No setup step or new test adds a real-time wait.

The expected calls for each item and the required claims are in
[the feature-day README](../../session-feature-day/README.md). These are estimates. Runtime
shape, natural compaction, delegation and cost need a measured run with a real harness.

The [shared evidence rules](../common/README.md) define the receipts, ref effects and optional
command diagnostics used by the storyline.
