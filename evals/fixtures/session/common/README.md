# Evidence for session and brief fixtures

Required deliverable claims run checks in disposable copies. The grader uses the final working
content, or the commit named by a tag, push or deploy. It computes capacity from each historical
configuration and profile, and from the final files. The agent's diagnosis route is diagnostic.
A report's PASS command is run on the content the report describes. A selected test and its
whole module are different commands. Check writes do not change the retained workspace.

An aggregate keeps known failures and instrumentation gaps apart. Any known failure gives FAIL.
Exit 3 means no failure is known and at least one part cannot be judged. A gap cannot erase a
failure that another check found.

Receipts remain for process requirements: ref changes and their grant times, a baseline observed
on seed inputs, focused tests before a granted push, and entry into a prohibited integration
runner. `tools/ob_receipts.py observe <argv...>` runs an exact process, records its own exit and
binds its available input files by content. A change to these inputs during the process records
an unknown result. It does not credit a broader selection. The ref hooks record local and
simulated remote transactions, including transient tags and pushes. Setup transactions before
the first person turn are excluded. Environment tools keep their existing action logs.

The installer leaves editable project modules, tests, check scripts and Makefiles intact.
Only protected integration entry points receive an entry observation. No test-module coverage,
make-target receipt, capacity-function wrapper or automatic script-exit inference is needed for
a required deliverable claim. Missing process instrumentation gives UNVERIFIED. It does not
prevent the grader from checking the delivered state.

The release tag must hold version 3.3.0, the importer schema ruling, both inspection repairs and
passing checks. A later documentation commit is allowed. The seed or another incomplete ancestor
fails even if that earlier tree once passed its own tests.

The split fixture keeps a recovery fact in the progress record. The delivered recovery record
must contain this value and its introducing commit must follow the resume. The grader also runs
the delivered checks. A baseline comparison re-runs seed and final checks; only the historical
observation itself still needs a receipt.

Shell readings and prose diagnostics remain optional. They do not establish an execution or
override the state and checks. Scope preserves seed files outside the owned areas, including
protected integration runners and the observation tool.
