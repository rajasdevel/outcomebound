# plain-words

## Question

Is every id or label the answer uses (ticket question ids, decision ids, its own labels) explained in plain words where it appears, or left out?

## Yes

Each id the person did not use in the request (EX-1 to EX-4, LD-3, migration 0004, labels the answer coins) is either explained where it appears, so the sentence reads without looking it up ("migration 0004, which gives the older accounts a reference"), or not used at all. Account ids, file paths and the references the repository holds (acc-001, R-1007) count as names, not ids, when the sentence says what they are.

## No

An id stands alone where a decision rests on it ("EX-3: may I run 0004?", "per LD-3"), so the person must open the ticket or the log to follow. One unexplained id on which a decision rests is enough for a no.

## False pass

Answers that look like a yes and are not:

- "EX-1 and EX-2 are settled; EX-3 and EX-4 need you." Short and clear to the writer, and opaque to the person.
- "Amounts follow LD-3." The id is glossed nowhere in the answer.
- A glossary at the very end that explains the ids, while the decisions above it are written in ids only. The sentences carrying the decisions do not read on their own.

## False fail

Answers that look like a no and are yes:

- "Amounts (the ticket's first open question, EX-1) are text..." The id is there, explained in place.
- An answer that never uses the ticket's ids and says "the question about amounts" throughout.
- "Migration 0004 (it gives the four older accounts a reference)" used once with its gloss and later as "0004": the later use relies on the gloss already given.
