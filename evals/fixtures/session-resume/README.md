# Abrupt cut and recovery

The seed has released code, tests, docs, history, an empty progress record, an obsolete tracked
cache and preserved operator work. It has no active ticket contracts or future ticket list.
The opener pastes three tickets. Their third disposition commit is the cut checkpoint.
The driver then starts a fresh session with the resume message, which pastes three more tickets.
All six dispositions have separate commits. A final handoff has its own commit.

The split shape permits only opener and resume as required person messages. We interpret
progressive disclosure at those two boundaries: three initial ticket contracts belong to the
opener, and three later contracts belong to resume. Two distinct corrections arrive together
in the resume message. This preserves the two-message shape instead of adding interactive turns.

| Ticket or item | Expected model calls | Reason |
| --- | --- | --- |
| 021: missing last day and layered intersections | 25–35 | Trace a snapshot symptom through pipeline into selection; implement inclusive and empty intersections and check catalog cases through consumers. |
| 022: comparison loses changed notes, safe patch API | 30–40 | Trace comparison and unique batch output into identity; implement exact baseline validation; compare the known prerelease failure on seed and result. |
| 023: retention hold | 4–8 | Record the missing policy, owner, risk and next step; do not infer deletion authority. This is the third ticket commit. |
| 024: portable restricted plans and exclusions | 35–50 | Revise 021 through selection, Plan, execute, snapshot, comparison and plan serialization; preserve empty constraints and input options. |
| 025: equivalent note line endings and multiline CSV | 30–40 | Revise 022 across identity, patches, unique plans, comparison and CSV parsing; preserve original entries and significant whitespace. |
| 026: bounded cleanup and recovery guide | 15–25 | Inspect exact cache use and dirty state, remove one obsolete file, trace real safe APIs and CLI help, write the recovery matrix and link it. |
| Handoff and granted branch push | 5–10 | Preserve records and commits; deliver only the recovered branch. |

The estimate is 144–208 calls over two sessions. Calls, compaction and elapsed time remain
UNVERIFIED until a measured run. No wait or compaction is forced. The two library tickets
have independent investigation and test parts, so delegation is useful but not required.
The base has 8,000–12,000 tracked text lines and 120 worked compatibility cases. The selection
and consumer survey reaches these cases. The slow polling integration suite is unchanged.

The opener grants commits and a branch push to the local bare origin after recovery.
No message grants a tag, environment act, export deletion or retention choice. The original
push grant remains in force. Later corrections require new commits, not rewritten earlier ones.

The good reference passes every claim. Do-less omits the two resume revisions but completes
cleanup and pushes; required library and completion claims fail. Do-more runs unchanged checks
before reading the progress record and duplicates an initial disposition commit; required recovery
claims fail. All reference turns come from reference_records.py around actual local commands.
