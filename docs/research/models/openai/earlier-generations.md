# OpenAI before GPT-5.6: GPT-4.1 to GPT-5.5, the Codex models and gpt-oss

How OpenAI's advice for prompting its models changed from GPT-4.1 (April 2025) to GPT-5.5 (April
2026), including the Codex-specialised line and the open-weight gpt-oss models. For anyone
maintaining text first written for these models, or reading why the current guidance says what it
says. Current models are in [gpt-6-family.md](gpt-6-family.md) and
[gpt-5.6-family.md](gpt-5.6-family.md); labels and ids as in
[../cross-family.md](../cross-family.md#evidence-labels-and-citations).

## Lineage (STABLE)

Each row is OpenAI's own claim unless tagged.

| Model | Released | What changed for prompting | Ids |
| --- | --- | --- | --- |
| GPT-4.1 | 2025-04-14 | Non-reasoning; follows instructions "more closely and more literally", so existing prompts "may not immediately work" as implicit rules are less strongly inferred. Three agent reminders (persist, use tools, optionally plan) worth about 20% on OpenAI's internal SWE-bench Verified run. The later of two conflicting instructions wins. All-caps and bribes unnecessary and possibly followed too strictly. In long contexts, put instructions above and below the material | openai-g1 |
| o3 / o4-mini; Codex CLI | 2025-04-16 | For reasoning models: simple direct prompts, no "think step by step", developer messages, zero-shot before few-shot, a precise end goal. Codex CLI launched reading `codex.md` and `~/.codex/instructions.md`. Transluce found a pre-release o3 fabricating actions [indep] | openai-g2 |
| GPT-5 | 2025-08-07 | `reasoning_effort: minimal` and a `verbosity` control; guidance on agentic eagerness; steerable tool preambles. Contradictions do more damage, since the model spends reasoning reconciling them. Cursor saw old "be THOROUGH" prompts cause tool overuse | openai-g3 |
| GPT-5-Codex | 2025-09-15 (Codex); 2025-09-23 (API) | "Less is more": many practices once prompted in are built in, "and over prompting can reduce quality"; start from a short prompt (the Codex CLI prompt is about 40% of GPT-5's); remove preamble prompting, which causes early stops; give it a terminal plus `apply_patch` | openai-g4 |
| GPT-5.1 | 2025-11-13 | Default effort `none`. Can be "excessively concise … at the cost of answer completeness", so persistence prompts re-added. Explicit length and format specs; have the model find contradictions in the prompt stack | openai-g5 |
| GPT-5.1-Codex-Max | 2025-11-18 (Codex); 2025-12-04 (API) | Long-horizon, native compaction; its prompt became OpenAI's recommended Codex starter. Status updates are generated by the system, so do not prompt for them. Cursor measured a 30% drop on Cursor Bench when GPT-5-Codex's reasoning traces were dropped (harness team) | openai-g6 |
| GPT-5.2 | 2025-12-11 | Adds `xhigh`. Follows instructions more closely but drifts in scope, so forbid extra features explicitly. Short, outcome-based updates. Migration method: switch with the prompt unchanged, pin effort, run evals, change one thing at a time | openai-g7 |
| GPT-5.3-Codex | 2026-02-05 (Codex); 2026-02-24 (API) | Preambles promptable again, only if the integration keeps the Responses `phase` field. Medium effort interactive, high/xhigh for long autonomous runs; mid-turn steering. Last full Codex-tuned model; Codex-Spark followed 2026-02-12, deprecated 2026-09-14 | openai-g8 |
| GPT-5.4 | 2026-03-05 | Codex coding merged into the flagship: 1M context, tool search, computer use, compaction. An output contract; a follow-through policy (proceed when reversible and low-risk, ask when irreversible, external or material); effort as a "last-mile knob"; "start with the smallest prompt that passes your evals". Mini and nano need longer, more explicit prompts | openai-g9 |
| GPT-5.5 | 2026-04-24 (API); 2026-04-23 (Codex) | "Not a drop-in replacement": rebuild from a fresh baseline. Outcome-first prompts with success criteria, allowed side effects, evidence rules and stop rules. Avoid step-by-step guidance unless the path matters. ALWAYS/NEVER/MUST only for true invariants. Default effort back to medium; higher is not automatically better. Stop including the date; move output schemas into Structured Outputs | openai-g10, openai-f8 |

## What carried forward and what reversed (STABLE)

- **Reversals within about 18 months** [openai-f17, openai-trend, openai-10]: persistence prompts in
  GPT-4.1 and 5.1, then GPT-5.6 Sol's high workaround-seeking, then GPT-6 Astra's hesitation;
  preambles encouraged (GPT-5), removed (GPT-5-Codex), promptable again with `phase` (GPT-5.3-Codex);
  "require thorough testing" became "unnecessary testing" with Astra.
- **Default effort:** `none` on GPT-5.1 and 5.2, back to `medium` from GPT-5.5 [openai-f18].
- **Reasoning across turns:** the Responses API carries reasoning (GPT-5); Cursor measured a 30% drop
  when reasoning traces were dropped (harness team) [openai-g3, openai-g6].
- **Date in prompts:** GPT-5.5's guide says to stop including it [openai-g10].
- **Smaller tiers:** GPT-5.4 mini and nano need longer, more explicit prompts [openai-g9].
- **Instruction capacity (indep):** GPT 5.5 held about 99% named-item inclusion through 5,000 items
  (one dip at 4,000) [measured-g10]; IFBench put GPT-5.5 at 75.9% [measured-g11]; its
  multiple-constraint half-life was 7 (GPT line 2 → 7 in one study) [measured-g16, measured-f2].
- An Artificial Analysis snapshot of 2026-04-30 put Kimi K2.6, MiMo V2.5 Pro and DeepSeek V4 Pro 3–6
  points behind GPT-5.5 on its Intelligence Index [open-weight-f21].

## gpt-oss (open weights)

OpenAI's gpt-oss-120b and gpt-oss-20b (August 2025, Apache-2.0 [review]) remain its newest open
weights apart from the gpt-oss-safeguard variants [chk-gptoss]. The research did not cover how to
prompt them, and they add no trend evidence.

## Lifecycle (VOLATILE)

- GPT-5.4 left Codex for ChatGPT-signed-in users on 2026-08-31.
- GPT-5.5 is scheduled to leave ChatGPT and Codex on 2026-10-14; the API is unaffected
  [openai-next].
- Codex-Spark (2026-02-12) was deprecated 2026-09-14 [openai-g8].
